# Генераторы

Ленивый перебор перестановок и сочетаний.

## Перестановки

**Heap's algorithm** — O(n!) по времени, O(n) по памяти. Ленивый: следующая перестановка вычисляется только при запросе.

```csharp
using static Combinatorics.Combinatorics;

foreach (var p in Permutations(new[] { 1, 2, 3 }))
    Console.WriteLine(string.Join(", ", p));
// 1, 2, 3
// 2, 1, 3
// 3, 1, 2
// 1, 3, 2
// 2, 3, 1
// 3, 2, 1
```

**Граничные случаи:**

```csharp
Permutations(Array.Empty<int>()).Count();   // 1 — одна пустая перестановка
Permutations(new[] { 42 }).Single();         // [42]
```

**Количество перестановок = n!:**

```csharp
Permutations(Enumerable.Range(0, 5)).Count(); // 120
```

## Сочетания по элементам

`CombinationsOf<T>(items, k)` — все сочетания длины k.

**Важно:** имя `CombinationsOf`, а не `Combinations`, чтобы не конфликтовать с числовым `Combinations(n, k)`.

```csharp
foreach (var c in CombinationsOf(new[] { "A", "B", "C", "D" }, 2))
    Console.WriteLine(string.Join("", c));
// AB
// AC
// AD
// BC
// BD
// CD
```

**Из диапазона 0..n−1:**

```csharp
foreach (var c in CombinationsOf(5, 2))
    Console.WriteLine(string.Join(",", c));
// 0,1  0,2  0,3  0,4  1,2  1,3  1,4  2,3  2,4  3,4
```

## Сочетания по индексам

`EnumerateCombinationIndices(n, k)` — только индексы, без копирования элементов. Минимум аллокаций.

**Лексикографический порядок** гарантирован.

```csharp
foreach (var idx in EnumerateCombinationIndices(4, 2))
    Console.WriteLine(string.Join(",", idx));
// 0,1
// 0,2
// 0,3
// 1,2
// 1,3
// 2,3
```

## Сравнение методов

| Метод | Возвращает | Аллокации |
|---|---|---|
| `Permutations<T>` | `IEnumerable<T[]>` | O(n) на перестановку |
| `CombinationsOf<T>` | `IEnumerable<T[]>` | O(k) на сочетание |
| `EnumerateCombinationIndices` | `IEnumerable<int[]>` | O(k) на сочетание |

## Граничные случаи

```csharp
// k = 0 — одна пустая выборка
CombinationsOf(5, 0).Count();     // 1

// k > n — пустая последовательность
CombinationsOf(3, 5);             // пусто

// k = n — одна полная выборка
CombinationsOf(3, 3).Count();     // 1

// n = 0, k = 0 — одна пустая
CombinationsOf(0, 0).Count();     // 1
```

## Ленивость

Генераторы **не вычисляют всю последовательность заранее**. Можно прервать цикл:

```csharp
// Взять только первые 5 сочетаний из 20 по 10
var first5 = CombinationsOf(20, 10).Take(5).ToList();
```

**Важно:** даже для `C(20, 10) = 184756` сочетаний генератор не строит их все — только запрошенные.

## Производительность

- **Перестановки:** O(n!) — Heap's algorithm минимально возможен.
- **Сочетания:** O(C(n, k) · k) — каждое сочетание копируется один раз.
- **Индексы:** O(C(n, k) · k) без копирования элементов.

Подробнее — см. бенчмарки `GeneratorBenchmarks` и `FullSequenceBenchmarks`.

## Зачем это нужно

Иногда нужно **перебрать** все перестановки или сочетания, а не просто посчитать их количество. Для n = 10 число перестановок — 3.6 миллиона, для n = 12 — 479 миллионов. Материализовать их все в памяти невозможно. Ленивые генераторы решают эту проблему: вы получаете элементы по одному, потребляя O(n) памяти.

## Как это выводится

### Heap's algorithm

Классический алгоритм, порождающий все перестановки за **ровно n!−1 обменов** — минимально возможное число. Рекурсивная версия:

```
procedure generate(k, A):
    if k == 1: output(A)
    else:
        for i in 0..k-2:
            generate(k-1, A)
            if k even: swap(A[i], A[k-1])
            else: swap(A[0], A[k-1])
        generate(k-1, A)
```

Итеративная версия использует массив счётчиков `c[]` вместо рекурсии. Наша реализация — итеративная (нет переполнения стека).

### Генерация сочетаний

Сочетание — возрастающая последовательность индексов `0 ≤ i_1 < i_2 < … < i_k < n`. Начинаем с `[0, 1, …, k−1]` и на каждом шаге находим самый правый элемент, который можно увеличить, затем «сбрасываем» все правее.

**Пример:** n = 5, k = 3.
```
[0, 1, 2] → [0, 1, 3] → [0, 1, 4] → [0, 2, 3] → [0, 2, 4] →
[0, 3, 4] → [1, 2, 3] → [1, 2, 4] → [1, 3, 4] → [2, 3, 4]
```

Алгоритм порождает сочетания в **лексикографическом порядке** — иногда это важно.

## Где встречается

| Задача | Что использовать |
|---|---|
| Обход всех решений задачи коммивояжёра (n ≤ 12) | `Permutations` |
| Перебор всех подмножеств размера k | `CombinationsOf` |
| Генерация тестовых данных | Оба |
| Комбинаторный поиск (branch & bound) | Оба |
| Перебор всех порядков обработки задач | `Permutations` |

## Как это использовать на практике

### Ограничение по времени

Ленивый генератор позволяет **прервать** перебор:

```csharp
foreach (var p in Permutations(items))
{
    if (IsGood(p))
    {
        // нашли — выходим
        break;
    }
}
```

Для n = 12 это может сэкономить минуты: не нужно генерировать все 479 миллионов перестановок, если решение найдено на первых тысячах.

### Комбинаторный поиск

Классический пример: задача о рюкзаке, где нужно перебрать все сочетания предметов размера k. `CombinationsOf(items, k)` даёт именно то, что нужно.

### Комбинация с LINQ

```csharp
// Первые 10 сочетаний, содержащих элемент "A"
var combos = CombinationsOf(items, 3)
    .Where(c => c.Contains("A"))
    .Take(10)
    .ToList();
```

Ленивость гарантирует, что мы не материализуем все `C(n, 3)` сочетаний.

## Производительность

| Метод | Сложность | Аллокации на элемент |
|---|---|---|
| `Permutations<T>` | O(n!) | O(n) (копия массива) |
| `CombinationsOf<T>` | O(C(n,k) · k) | O(k) |
| `EnumerateCombinationIndices` | O(C(n,k) · k) | O(k) |

`EnumerateCombinationIndices` даёт минимум аллокаций — только индексы, без копирования самих элементов. Используйте его, если работаете с большими объектами.

## Типичные ошибки

**1. Забыть, что `Permutations` возвращает `IEnumerable`, а не массив.**

```csharp
var perms = Permutations(items);        // НЕ перебирает
var first = perms.First();              // перебирает до первого
var all = perms.ToList();               // материализует все
```

**2. Вызывать `Count()` на генераторе для больших n.**

```csharp
Permutations(items).Count();   // переберёт ВСЕ n! перестановок
```

Для n = 10 это 3.6 миллиона — займёт секунды. Лучше использовать `Factorial(n)`, если нужна только цифра.

**3. Модифицировать элементы внутри перебора.**

Генератор использует **тот же массив** и только клонирует его при `yield return`. Если вы модифицируете элемент (например, `p[0] = 5`), следующая итерация увидит изменение.

```csharp
foreach (var p in Permutations(new[] { 1, 2, 3 }))
{
    p[0] = 99;   // ПЛОХО: влияет на следующий шаг
}
```

Работайте с копией: `var copy = p.ToArray();`.

**4. Использовать `foreach` с `async` без осторожности.**

```csharp
foreach (var p in Permutations(items))
{
    await SomethingAsync(p);   // работает, но может быть медленно
}
```

Если нужно много перестановок и async-обработка — лучше параллелить через `Parallel.ForEach` (но это уже не ленивый генератор).

**5. Путать `CombinationsOf` с `Combinations`.**

```csharp
Combinations(5, 2);              // BigInteger = 10 (ЧИСЛО сочетаний)
CombinationsOf(items, 2);        // IEnumerable<int[]> (ПЕРЕБОР)
```

Первый — число, второй — генератор. Разные сигнатуры, разные задачи.
